# v7.8 실제 서버 수정·검증 보고서

첨부된 v7.7 소스의 실제 `buildScene()` 호출 경로를 수정했다. 신발 확대본의 잔가시와 불필요한 앵커는 줄었고, 주얼리 접합부도 정리됐다. 다만 **이미 글자와 테두리가 한 채움으로 합쳐진 주얼리는 자동 분리를 완료하지 못했다. 전체 샘플의 모든 끊김을 없앴다는 결과도 아니다.**

검증일: 2026-09-09. 이 패키지는 서버 소스, 원본 v7.7 ZIP, 고정 입력, 재현 스크립트, SVG·AI 출력과 검사 로그를 포함한다. 운영 데모 배포는 수행하지 않았다.

## 2. 연결성과 매끄러움을 함께 지키는 방법

### 골격과 파트 소유권

골격 픽셀의 대각선 이웃 사이에 이미 가로/세로 연결이 있으면 중복 대각선을 제외한다. 모든 그래프 간선을 한 번씩 따라가며, 분기점 좌표는 붙어 있는 획들이 공유한다. 가지 제거는 실제 자유 끝점에서 분기점으로 가는 짧은 경로에만 적용하고 분기점 픽셀은 남긴다. 닫힌 고리와 분기점 간 연결선은 이 규칙으로 지우지 않는다.

파트 소유권은 선을 만든 후 부여한다. 서로 다른 파트로 나눠야 할 때 De Casteljau 분할을 사용하므로 같은 곡선의 접점을 공유한다. SVG 좌표 직렬화 정밀도는 기존처럼 소수 둘째 자리이며, 기하 연산의 정확한 접점을 내보내는 과정에는 이 반올림이 있다. 파트 라벨의 의미 자체를 새로 인식하는 기능은 아니다.

### 곡선 피팅

호 길이로 다시 표본화한 점들에 대해 다음 형태의 문제를 푼다.

`min Σ ||C(u_i) − p_i||² + λ Σ ||P[i−1] − 2P[i] + P[i+1]||²`

양 끝점을 고정하고, 지속되는 실제 코너와 다른 획의 접합점에서 구간을 나눈다. 매끄러운 구간은 cubic B-spline으로 맞춘다. 단순 내부 knot에서 C2 연속성이 성립하며, 코너를 보존하기 위해 나눈 구간 경계까지 C2를 강제하지는 않는다. knot 수를 늘려도 예산 안에서 맞지 않으면 기존 피터를 사용한다. 전체 곡선 피팅 예산은 세 가지를 시도하되 최종 허용 이탈은 동일하게 유지한다.

채택 조건은 다음과 같다.

- 입력 벡터와 결과의 양방향 거리: 기본 원본 2px 이하.
- 새 자체 교차 및 다른 획과의 교차를 추가하지 않을 것.
- **짧은 획을 포함한 기존 접합점**과의 거리를 유지할 것.
- 앵커 수가 증가하지 않고, 방향 변화의 불규칙성이 악화되지 않을 것.

거리와 교차 검사는 조밀한 표본 선분에 대한 수치 검사다. 해석적인 곡선 증명이나 원본 사진과의 오차 상한은 아니다. 2px 상한은 **이 마감 단계 직전 벡터**를 기준으로 하며, 그 이전 생성·벡터화 오차까지 2px이라고 주장하지 않는다.

### 틈과 잔가지

새 미세 틈 연결은 기본 원본 3px 안에서 방향, 거리, 상호 후보의 유일성, 파트 관계, 교차/채움 가림을 검사한다. 이 경우는 형상에 근거한 추정임을 보고서에 기록한다. 원본에 잉크가 없는 큰 빈 공간을 자동으로 가로지르지 않는다. 기존 `gapBridge.ts`의 먼 틈 잉크 검사는 유지한다.

잔가시는 긴 본선에 붙은 짧은 자유 가지를 대상으로 한다. 큰 획에 합쳐진 끝 갈고리는 기존 접합 앵커에서만 잘라낸다. 체인·바느질·레이스·텍스트로 명명된 파트와 보호 플래그는 삭제에서 제외한다. 독립적인 작은 잔흔도 긴 윤곽 하나의 근처인지 확인한다. **파트 라벨이나 보호 정보가 잘못되면 실제 짧은 디테일과 잔가시를 혼동할 여지가 있다.** 이를 4개 샘플만으로 일반적으로 해결했다고 보지 않는다.

## 3. 굵은 글자와 얇은 테두리

외곽선은 기본 원본 1.4px를 상한으로 하고, 채워진 글자에는 이 선 굵기 상한을 적용하지 않는다. 글자 마스크가 인식 박스 바깥으로 번지지 않도록 했으며, 이미 생성된 글자에는 주변 구조선과 원본 2px 간격을 만들 수 있는지 검사한다.

실제로 다시 벡터화한 결과에서 간격을 검사한다. 픽셀 마스크에서만 간격이 생겼다는 이유로 통과시키지 않는다. 글자의 두꺼운 내부 영역이 손상되거나 재추적 곡선이 간격을 침범하면 원래 글자를 유지하고 REVIEW 사유를 남긴다. 두꺼운 내부 잉크 보존은 폰트·철자·브랜드 정체성 검증과는 다르다.

**실제 jewelry_1의 gl1은 테두리와 여러 글자가 하나의 채움이다. 분리 후보의 두꺼운 내부 잉크 보존 비율이 약 72.6%여서 거절했다. 해당 글자 간격은 미해결로 남아 있다.** 후처리만으로 글자와 테두리의 공유 픽셀 소유권을 확실하게 복원하기 어렵다. 이 부분을 완결하려면 원본 도식의 글자/몸체 경계 마스크를 교정하거나, 정확한 글자 원형을 별도로 제공해 배치해야 한다.

## 4. 검증 결과 — 서로 다른 두 범위

### A. 사용자가 첨부한 확대본을 실제 서버 추적 경로로 A/B

동일 PNG, 네이티브 해상도, `lineMode=true`, `strokeLines=true`, `thinFinish=true`, `widthGrades=3`, `textureMode=keep`를 사용했다. v7.7 원본과 수정한 `buildScene()`를 각각 실행했다. 사진 생성 모델이나 의미 파트 분할을 새로 실행한 검증은 아니다. 작은 확대본은 전체 그림의 의미 문맥을 포함하지 않는다.

| 입력 | 앵커 | 감소 | 패스 |
|---|---:|---:|---:|
| 첨부 신발 확대본 | 93 → 46 | 50.5% | 29 → 16 |
| 첨부 주얼리 접합부 | 20 → 16 | 20.0% | 6 → 5 |

비교 그림: `comparison.png`. 실제 벡터는 `results/crops/*-after/production.svg`, AI는 같은 폴더의 `layered.ai`에 있다. 중간에 더 적은 앵커 후보도 있었지만, 접합점·교차 보존 검사를 적용한 최종 값만 위에 기록했다.

### B. 공개 데모 4개 샘플의 고정 편집 데이터를 재처리

공개 샘플 목록과 개별 `doc`, `production.svg`, `schematic.jpg`를 읽기 전용으로 확보했다. 입력 SHA-256은 `results/validation/replay-summary.json`에 있다. 원래 파트/패턴 정보를 보존한 상태에서 새 최종 마감 처리를 재생했다. **이 표는 새 골격 추적·새 모델 생성·새 파트 마스크 분할까지 다시 실행한 결과가 아니다.** 편집 데이터에는 upstream 마스크와 원래 qaWidth가 없기 때문에 전체 사진→AI 파이프라인의 충실도·의미 QA를 통과했다고 주장하지 않는다.

| 샘플 | 앵커 | 감소 | 패스 | 제거: 가지/갈고리/잔흔 | 미세 연결 | 처리 시간 |
|---|---:|---:|---:|---:|---:|---:|
| jewelry_1 | 316 → 302 | 4.43% | 60 → 60 | 0 / 0 / 0 | 0 | 6.09초 |
| shoe_1 | 1,090 → 1,023 | 6.15% | 289 → 273 | 12 / 0 / 4 | 0 | 17.67초 |
| bag_2 | 1,096 → 1,078 | 1.64% | 245 → 244 | 1 / 0 / 0 | 0 | 15.35초 |
| bag_3 | 4,412 → 4,409 | 0.07% | 235 → 235 | 0 / 0 / 0 | 0 | 0.59초 |

시간은 이 실행 환경에서 후처리와 파일 출력 일부에 걸린 시간이다. 전체 생성 시간의 개선율로 비교할 수 없다. bag_3의 반복 인스턴스는 328개를 유지한다. 대부분의 앵커가 복잡한 채움 패턴에 있어 구조선 마감만으로 전체 앵커를 크게 줄이지 못했다.

연속성은 양쪽 모두 **새 동일 측정기**로 측정했다. `freeLong`은 긴 획의 자유 끝점이며 정상적인 열린 끝도 포함한다. `splitJoins`는 맞닿은 다른 패스의 끝점 수여서 고유 틈 개수가 아니다.

| 샘플 | 긴 자유 끝점 전→후 | 맞닿은 분리 패스 끝점 전→후 |
|---|---:|---:|
| jewelry_1 | 15 → 15 | 6 → 6 |
| shoe_1 | 124 → 124 | 39 → 39 |
| bag_2 | 32 → 32 | 2 → 2 |
| bag_3 | 11 → 11 | 27 → 27 |

**전체 샘플의 긴 자유 끝점 수를 줄였다는 증거는 없다.** 위 표는 잔가시/앵커 개선 과정에서 이 수를 늘리지 않았음을 보여준다. 큰 무잉크 틈, 가림, 글자와 공유한 경계는 별도 의미 복원이 남아 있다.

신규 회귀검사 33개, 기존 연결선 검사 10개가 통과했고 TypeScript 검사도 통과했다. 골격 대각선, 연결선 예산, 파트 접점, 1·2·4배 스케일, 평행선 오연결 방지, 채움 내부 연결 금지, 갈고리, 체인 보호, 짧은 접합점 보존, 글자 분리 실패의 REVIEW 처리 등을 포함한다. 기록은 `results/validation/`에 있다.

동일한 jewelry_1 편집 데이터를 두 번 처리한 SVG의 SHA-256이 같았다. 이 검사에는 GPT 호출이 없다. 과거 9종의 확률적 모델 A/B 결과를 다시 검증했다는 뜻이 아니다.

## 5. 적용 및 재현

실제 연결 위치: `run4.ts` → `buildScene()` → `cleanFinish()` → SVG/AI 내보내기 → QA. `thinFinish` 경로에서 새 마감이 실행된다. 단순히 별도 실험 스크립트만 추가한 패키지가 아니다.

```bash
npm ci
npm run typecheck
npm run test:clean
node --import tsx server/v4/tools/connectortest.ts
npm run validate:clean
```

단일 기존 장면을 재처리하려면:

```bash
npm run reprocess:clean -- scene.json output-directory
npm run reprocess:clean -- fixtures/live-v7.7/jewelry_1/editor-doc.json output-directory fixtures/live-v7.7/jewelry_1.json
```

두 번째 명령은 공개 편집 데이터의 기하 재생이며 전체 QA를 대신하지 않는다. 각 샘플 결과에는 `production.svg`, `layered.ai`, `by-part.ai`, `by-color.ai`, `scene.json`, `report.json`, 전후 PNG가 있다. AI 파일은 기존 내보내기 코드를 통해 생성했으며 Adobe Illustrator GUI에서 직접 열어 확인한 것은 아니다.

원본 v7.7과 확대본 A/B를 재현하려면:

```bash
mkdir -p baseline/v7.7
unzip baseline/v7.7-source.zip -d baseline/v7.7
ln -s ../../node_modules baseline/v7.7/node_modules
node --import tsx scripts/test-crop-pipeline.mts baseline/v7.7 fixtures/user-crops/shoe-spurs.png results/crops/shoe-before
node --import tsx scripts/test-crop-pipeline.mts . fixtures/user-crops/shoe-spurs.png results/crops/shoe-after
```

첨부 소스의 HANDOFF 설명대로 운영 데모는 별도 저장소의 `backend/flat/server`를 사용한다. 그 경로에 수정된 서버 전체를 반영하거나 기존 동기화 절차를 실행해야 한다. **저장된 샘플 결과는 코드 배포만으로 바뀌지 않는다.** 전체 개선을 보려면 기존 사진/도식·마스크 캐시에서 새 서버 파이프라인으로 샘플을 재생성하고, 데모가 읽는 SVG/AI/scene/미리보기와 버전 메타데이터를 함께 교체해야 한다. 공개 편집 데이터 재생 결과는 중간 확인용이다.

원본 소스와의 코드 차이는 `source-changes.patch`에도 포함했다. 운영 저장소나 다른 사용자의 변경 사항에 자동 적용·배포하지 않았다.

| 설정 | 기본값 | 역할 |
|---|---:|---|
| `V4_CLEAN_CONTOURS` | 활성 | buildScene의 새 최종 마감 호출. 0이면 마감 생략 및 이전 straight-run 병합 사용 |
| `V4_CLEAN_OUTLINE_PX` | 1.4 | 원본 좌표 기준 구조선 굵기 상한 |
| `V4_CLEAN_DEV_PX` | 2 | 마지막 곡선 피팅의 허용 이탈 |
| `V4_CLEAN_GAP_PX` | 3 | 형상 기반 미세 틈 연결 상한 |
| `V4_CLEAN_SPURS` | 활성 | 가지·갈고리·잔흔 정리 |
| `V4_CLEAN_SPUR_PX` | 18 | 짧은 가지/갈고리 길이 상한; 길이만으로 삭제하지 않음 |
| `V4_CLEAN_SPECK_PX` | 6 | 작은 잔흔 크기 상한; 0이면 해당 정리 끔 |
| `V4_GLYPH_CLEARANCE` | 활성 | 글자 간격 검사·수정 |
| `V4_GLYPH_GAP_PX` | 2 | 원본 좌표 기준 글자와 구조선 사이 간격 |

`V4_CLEAN_CONTOURS=0`은 원본 v7.7 전체를 복원하는 스위치가 아니다. 골격/파트 추적 코드도 바뀌었기 때문에 정확한 A/B 기준은 동봉한 원본 소스를 사용해야 한다.

## 6. 관련 공개 코드·연구와 이번 구현의 관계

Schneider의 FitCurves 구현은 매개변수화, 최소제곱 큐빅 피팅, 재매개변수화, 최대 오차점 분할의 참고 자료다. 기존 피터를 유지하면서 호 길이 접선, 순서를 지키는 Newton 갱신, 전체 구간 spline 후보와 독립적인 거리 검사를 추가했다. 논문의 전체 알고리즘을 그대로 이식했다고 주장하지 않는다. [Graphics Gems / FitCurves.c](https://github.com/erich666/GraphicsGems/blob/master/gems/FitCurves.c)

VTracer는 래스터의 영역을 벡터 곡선으로 추적하는 도구다. spline 출력도 지원하지만, 결과가 곡선이라는 사실만으로 ‘한 의미적 외곽선 = 한 편집 가능한 획’이나 글자/테두리 소유권이 보장되는 것은 아니다. 이번 구현은 채움과 글자에는 기존 벡터 추적을 사용하고, 선에는 중심선 그래프와 곡선 피팅을 사용한다. [VTracer 공식 저장소](https://github.com/visioncortex/vtracer)

PolyVector Fields 연구는 접합부의 올바른 연결 구조 복원을 중요한 문제로 다룬다. 이 관점은 본 사례에서 부분 곡선의 픽셀 적합도만 높이는 것보다 접합점·연결 그래프를 먼저 지켜야 하는 이유와 맞닿는다. 해당 논문 구현이나 학습 모델을 이번 서버에 추가한 것은 아니다. [Vectorization of Line Drawings via PolyVector Fields](https://arxiv.org/abs/1801.01922)

End-to-End Line Drawing Vectorization은 stroke encoder/decoder/vectorizer를 결합해 획 분할과 벡터화를 함께 학습하는 접근이다. 현재 후처리만으로 해결하기 어려운 과분할·의미적 연결 문제의 다음 연구 방향이 될 수 있으나, 이 패션/주얼리 샘플에서 성능이 검증된 대체 모델로 제안하는 것은 아니다. [AAAI 2022 원문](https://cdn.aaai.org/ojs/20379/20379-13-24392-1-2-20220628.pdf)

특정 샘플 좌표나 ID를 알고리즘에 하드코딩하지 않았다. 다만 고리·각인·봉제선을 보호하려면 올바른 파트/보호 정보가 필요하다. 이 패키지는 확인된 코드 원인과 측정 결함을 고친 결과이며, 모든 제품 사진에서 무결점 벡터를 보장하는 범용 해법은 아니다.
